# Project structure

Which directories mean what, which files you own, and which ones the generator overwrites.

## Layout

```
myapp/
  gossr.yaml                  config; its location defines the project root
  go.mod
  main.go                     your entry point
  internal/web/               webDir
    web.go                    mounts pages.NewSsrHandler
    package.json              npm dependencies for the asset pipeline
    webpack.config.js
    tsconfig.json
    webpack-assets.json       written by webpack, read by the generator
    dist/                     webpack output (development)
    pages/                    the route tree
      index.html              route "/"
      index.ts                optional per-route TypeScript entry
      styles.scss             optional per-route stylesheet
      dataprovider.go         yours
      ssrroute_gen.go         generated
      ssrhandler_gen.go       generated, only in pages/
      ssrstaticfiles_gen.go   generated, only in pages/
      static_embed/           generated staging dir for embedded assets
      users/
        index.html
        dataprovider.go
        _userId_/
          index.html
          dataprovider.go
```

`webDir` is resolved relative to `gossr.yaml`, so the tool can be run from any subdirectory of the project.

## Files in a route directory

| File | Owner | Purpose |
|---|---|---|
| `index.html` | you | the template; a directory without one is not a route |
| `dataprovider.go` | you | implements the route's `RouteDataProvider`; created as a stub only when missing |
| `index.ts` | you | optional TypeScript entry point, bundled into this route's chunk |
| `styles.scss` | you | optional stylesheet, bundled into this route's chunk |
| `ssrroute_gen.go` | generator | rendering code and generated types; never edit |
| `__ssr_gen__.ts` | generator | the typed reactive client, only for routes with reactive variables |
| other `.go` files | you | helper types used by the template (`User`, for example) live in the same package |

A route directory is a Go package named after the directory, so `pages/users/_userId_/` is package
`_userId_`. Types referenced from a template must be visible in that package.

## Generated files

Generated Go files start with:

```go
// Code generated by github.com/sergei-svistunov/go-ssr. DO NOT EDIT.
```

They are rewritten on every generation and are meant to be committed, so that `go build` works without
running the generator first.

## Reserved names

| Name | Why |
|---|---|
| `__ws` | reserved for the generated WebSocket endpoint of a reactive route; a directory with this name is an error (see `errors`) |
| `static_embed` | the staging directory under `pages/` for the embedded static blob; a route cannot share the name |
| `index.html`, `index.ts`, `styles.scss` | fixed per-route file names |
| `dataprovider.go`, `*_gen.go`, `__ssr_gen__.ts` | fixed generated or convention file names |

A directory whose name is wrapped in underscores — `_userId_` — is a dynamic URL parameter, not a literal
path segment. See `routing`.

## Where the deps package goes

When `depsPackage` is set in `gossr.yaml`, every generated `NewDP` takes a pointer to that package's type, so
routes can reach a database handle or an application model. The deps package must not import anything from
the `pages` tree, otherwise the import cycle makes the project unbuildable. A sibling package such as
`internal/model` is the usual home. See `config`.
